# 플레이테스트 케이스

Autopilot(AI 플레이)과 프로브(측정 스크립트)로 확인하는 항목 목록. 실행할 때마다 **이력**에 한 줄씩 더한다.
실행 방법은 [`../AUTOPILOT.md`](../AUTOPILOT.md), 실행별 상세는 같은 폴더의 날짜 파일.

원칙
- **"다 통과"가 목표가 아니다.** 봇은 일부러 실력을 나눠 둔다(Bot1 0.9 → 마지막 봇 0.55, `FeelPrototype.BotSkillBest/Worst`).
  잘하는 봇은 자주, 못하는 봇은 가끔 완주하는 **분포**가 맞는지 본다.
- 한 가지 숫자만 보지 않는다: 어디까지 갔나, 어디서·왜 떨어졌나, 몇 번·몇 초에 완주했나를 같이 잰다.
- 판정은 플레이(에피소드)나 측정 프로브로 낸다. 코드만 보고 통과라 쓰지 않는다.
- 기대 범위가 아직 정해지지 않은 항목은 **(제안)** 으로 적고, 사용자가 정하면 고친다.

## 측정 도구

| 도구 | 내용 |
|---|---|
| `tools/autopilot/lib.py` → `race_census(game, seconds)` | 봇 전원이 레이스를 달리는 동안 봇마다 실력·최고 구간·체크포인트·완주 수·완주 시간·구간별 낙하(원인: `knocked` 맞아서 / `off_edge` 스스로) 기록 |

- Autopilot 실행 중 프로브에서 쓴다: `import lib; out = lib.race_census(game, 100); lib.print_census(out, 100)`.
- 저장소의 `tools/autopilot/lib.py` 가 원본이다. Autopilot 게임 폴더(`%LOCALAPPDATA%\Autopilot\memory\SushiRun\lib.py`)에 복사해서 쓴다.
- 프로브 시간은 실행 한 번에 10분이다(첫 에피소드 전). 긴 측정은 실행을 새로 시작해서 한다.

## 케이스

### TC-SD-01 아레나 시작·부활 직후 꼬치 정지
- 확인: 아레나 생성(2번 키)·플레이어 부활 뒤 꼬치가 `StartHoldSeconds`(2.5초) 동안 멈추고, 멈춘 동안 꼬치에 닿아도 넘어지지 않는다.
- 측정: `Rotator.IsHolding` 이 풀리는 시각, 넘어진 시각(`Mode == Down`)과 그때 정지 여부. 봇 공격(`AttackAbility.CooldownRemaining` 가 8로 뛰는 것)과 구분한다.
- 통과: 정지 2.4~2.6초, 정지 중 꼬치로 넘어짐 0회.

### TC-SD-02 탈락 후 꼬치 속도 초기화
- 확인: 플레이어가 떨어졌다 돌아오면 꼬치 속도가 낮은 40°/s · 높은 30°/s 로 돌아가고 버틴 시간이 0으로.
- 통과: 매번 40/30.

### TC-SD-03 정지 중 봇 공격 없음
- 확인: 꼬치 정지 2.5초 동안 봇이 공격하지 않는다(`PrototypeLevel.BotAttacksPaused`, #8).
- 측정: 아레나 생성 직후 3초 동안 봇들의 `CooldownRemaining` 변화.
- 통과: 정지 중 공격 0회, 정지가 끝난 뒤에는 다시 공격함.

### TC-UI-01 튜닝 패널 열면 조작 막힘
- 확인: Tab 패널이 열려 있으면 W를 눌러도 이동 입력이 0.
- 측정: 레이스 출발대에서(꼬치에 맞지 않는 곳) `PlayerInputReader.InputEnabled`, `MoveWorld`, 위치 변화. 패널 닫고 대조.
- 통과: 열림 = 입력 0·이동 0, 닫힘 = 이동함.

### TC-RACE-01 봇 레이스 분포 (`race_census`)
- 확인: 봇이 코스를 실력대로 나아가고 일부는 완주한다.
- 측정(봇마다): 실력, 방해꾼 여부, 공격 횟수, 최고 구간, 체크포인트 수, 완주 수·시간, 구간별 낙하와 원인.
- 통과 기준 **(제안)**: 100초 측정에서
  1. 실력 0.8 이상 봇 중 1명 이상 완주
  2. 실력이 높을수록 평균 최고 구간이 멀다(대체로 단조)
  3. 최하위 봇(0.55)은 완주가 드물다 — 0회도 허용
  4. 한 구간이 낙하의 80% 이상을 차지하지 않는다(특정 장애물만 벽이 되지 않게)

### TC-BOT-01 방해꾼 봇
- 확인: 방해꾼 봇(`WanderBot.Troublemaker`, `FeelPrototype.TroublemakerBots` = 마지막 봇부터 N명)이 가까운 상대(사람 플레이어 우선)를
  잠깐씩 쫓아가 밀고·때리고·다이브로 들이받는다. 판정·능력치는 다른 봇과 같고 행동만 다르다.
- 측정(`race_census`): 봇마다 공격 횟수(`attacks`), 방해꾼 여부, 그리고 다른 봇의 `knocked` 낙하가 방해꾼 근처에서 늘었는지.
- 통과 기준 **(제안)**: 방해꾼 공격 횟수가 일반 봇의 3배 이상, 방해꾼 자신도 가끔은 앞으로 나아감(최고 구간이 출발대에 머물지 않음).

### TC-RACE-02 플레이어(AI 에이전트) 완주
- 확인: 사람 조작과 같은 입력으로 결승선을 통과할 수 있다.
- 측정: 에피소드에서 체크포인트·완주 여부, 낙하 위치·원인(화면 확인).
- 통과: 완주 1회 이상.
